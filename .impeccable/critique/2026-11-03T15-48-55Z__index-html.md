## Design Specificity Verdict

**LLM assessment:** The look is distinctive but not specific to Wael. The amber/ink/parchment palette with Bungee, Plex and Silkscreen is a real identity and avoids the generic dev-portfolio template. The retro-arcade costume, though, is well-worn: PLAYER ONE, Quest Log, Loadout, Insert Coin, Save File, Lobby, Konami. Any game-adjacent CS student could wear it. Nothing in the frame comes from Wael:
- not Thurayya Studio (Arabic for the Pleiades, an unused hook)
- not the Khobar / Arabic–English context
- not the founder story
- not real work visuals

The metaphor helps a game-studio recruiter's first impression and hurts a web recruiter's fast read. That breaks the "both tracks count equally" principle.

## Overall Impression

Confident first frame, strong name lockup, honest copy and good accessibility groundwork. But the page spends its best real estate on props and its weakest on proof. The single biggest opportunity: make the Projects section the peak. Add real links and honest thumbnails, and move the arcade costume from the whole frame to one or two accents.

## What's Working

1. **Honest, specific copy under the costume.** It names real things (IAU, May 2027, Khobar, Thurayya with a working link, Jan 2025–present), and the H2s stay plain so scanning still works.
2. **A real type and color identity** that holds across both themes, not a default template.
3. **Accessibility groundwork:**
   - skip link and a visible `:focus-visible` ring
   - reduced-motion respected
   - `aria-expanded` and Esc on the menu
   - theme applied before paint
   - content visible without JS

## Priority Issues

**[P1] The Projects section shows no proof.**
- **Why it matters:** this is the section recruiters come to verify ("Show proof" principle).
- **Problems:**
  - no repo links, even for the public Iqraa repo
  - two placeholder thumbnails presented as real
  - "Placeholder" alt text on the real Pexet image
  - "Read more" panels that repeat the summary
  - "PROJECTS BUILT 10" next to 3 cards
  - mixed thumbnail aspect ratios
- **Fix:**
  - add "View code ↗" on Iqraa and a "Private · in development" label on Pexet
  - use a fixed 16:10 frame with `object-fit`
  - label placeholders honestly
  - fill "Read more" with what Wael built and decided, or drop it
  - make the stat match reality or link to GitHub
- **Suggested command:** /impeccable clarify, then /impeccable layout

**[P1] Arcade props own the hero and the hierarchy.**
- **Why it matters:** in a 30-second skim, half the first screen tells a web recruiter nothing, and the red "TIME TO GRADUATE" bar reads like low health.
- **Problems:**
  - the PLAYER.CARD (trophy "portrait", HP bar, LIVE badge, empty stat) has zero facts
  - fake stat bars in About
  - a non-interactive blinking CONTINUE
  - eight game eyebrows
  - a crosshair cursor over prose
- **Fix:**
  - replace the card with a factual at-a-glance panel: Now / Seeking / Tracks / top stack / CV
  - remove the decorative bars
  - keep the game voice in the arcade section, the Pexet card and the footer
- **Suggested command:** /impeccable distill

**[P1] Contrast and legibility failures, including on the primary CTA.**
- **Why it matters:** the main CTAs become unreadable at the exact moment someone reaches for them, and light-theme visitors get sub-AA body text.
- **Problems:**
  - hover turns `.btn-primary` links to 1.18:1
  - light-theme `--muted` is 3.83:1
  - light-theme `--accent-strong` text is 2.70–3.05:1
  - 25 labels sit at 9.9–11.5px in caps pixel type with wide tracking
  - the player card's hard-coded dark rgba leaks into light theme
- **Fix:**
  - scope the hover color away from `.btn`
  - darken the light-theme muted and amber text tokens to ≥4.5:1
  - set a 12px floor for Silkscreen and limit it to short labels
  - turn the player-card colors into tokens
- **Suggested command:** /impeccable colorize + /impeccable typeset (or /impeccable audit to verify)

**[P1] The mini-game hijacks the page.**
- **Why it matters:** for game studios this is the craft sample, and right now it shows weak input handling.
- **Problems:**
  - R and ←/→ are captured page-wide
  - it runs off-screen
  - no `touch-action: none` on the canvas, so mobile drags scroll the page
  - the "Dodge" title contradicts the catch mechanic
  - no final score
  - hard-coded colors
  - no live score for screen readers
- **Fix:**
  - take input only when the canvas is focused (`tabindex=0`)
  - pause via IntersectionObserver and on blur
  - add `touch-action: none`
  - rename it to "Catch the blocks"
  - show a final score plus a best score in `localStorage`
  - read colors from CSS vars
  - add an `aria-live` score
- **Suggested command:** /impeccable harden, then /impeccable delight

**[P2] The hard-shadow system is broken and the mobile header is misaligned.**
- **Why it matters:** the signature retro depth is silently missing, and the press-down button hover has nothing to press.
- **Problems:**
  - `4px 4px 0 var(--shadow-hard)` expands to an invalid value on every button, card, stat, chip group, brand mark and toast
  - at ≤640px the theme/menu buttons sit next to the logo, leaving the right half of the header empty
- **Fix:**
  - add a `--shadow-color` token
  - add `margin-left: auto` on `.hud-actions`
- **Suggested command:** /impeccable polish
